# ADR 1030 — A URL-bearing value is reduced by the parser or it is redacted

**Status:** Accepted (2026-07-24) — HQ-ruled default, Martin ratify queued (do-first doctrine, security lane). **Replaces the design** of [ADR 1011](1011-client-sentry-url-query-scrub.md) / [ADR 1013](1013-posthog-analytics-url-scrub.md) and everything layered on it through [ADR 1025](1025-heatmap-merge-must-not-use-set-and-the-sdk-masks-nothing.md). Those ADRs are not superseded in their findings — every defect they record is real and is in the acceptance corpus below — but their shared **shape** is abandoned.

That take deletes any repo-local addition, and perimetra carries six entries the skeleton does not — `recipient_email`, `ico`, `dic`, `address_line`, `city`, `postal_code` — because they are this repo's own `pii()` columns, obliged by the [ADR 0040](0040-gdpr-privacy-audit.md) mirror for exactly the reason the skeleton carries `name`/`image`/`identifier` and web-native does not. Without them the chain's NAME-EXTRACTION seam has no regression guard — narrowing it to `attr__`-prefixed names left the entire committed telemetry suite green while a chain shipped `href="/clients?search=Novakova"` verbatim. That is pre-existing, not introduced here (the pre-drain `dropUrlQuery` preserved the path identically), it is not live (no deploy target), and it needs its own slice before the soft-release. Recorded in the vault as _A URL scrubber that keeps the pathname is only safe while no credential lives in a path segment_.

## Context

Six successive adversarial review rounds ran over this redaction lineage. Every round declared the code correct. Every round was falsified by the next round's execution. The full cold cache-busted gate was GREEN in both skeletons throughout all six.

The vault finding states the generalisation, and it is the premise of this ADR:

> **The defect class recurs at whatever carrier the current model does not describe.** Each round modelled the value as _one URL identified by a name I can allow-list_, and each was defeated by a value shape outside that model: a non-special scheme's opaque host, a path vs an authority, a second (then third) representation of the same data, a namespaced name, a list-valued attribute.

Enumerating the modelled cases buys exactly one round. So the enumeration is not extended again. The rule is inverted.

### What must be true of the replacement

1. **An unmodelled shape REDACTS.** Not "passes through", not "is handled by a later sink".
2. **No returned byte is unexamined.** Round 6's ADR named "a safe answer produced by handing back input bytes never examined" as the root cause, and its own new gate did exactly that. Every safe answer this design produces is **re-serialized from parser fields**, never sliced out of the input.
3. **No local rule may infer a boundary from surrounding bytes.** Whoever controls an href controls the bytes a heuristic reads. Every boundary this design uses is either the URL parser's or a hard REDACT.

## Measurements taken before designing

Against the installed producer, `posthog-js@1.379.2`, `dist/module.js`. These are executed reads of the shipped bundle, not documentation.

**M1 — the session-entry family is generated by string concatenation, not enumerable.**

```js
I = function (t) { return t.replace(/^\$/, ""); }
getSessionProps() {
  var t = {};
  sr(ur(this.getSetOnceProps()), (e, i) => {
    "$current_url" === i && (i = "url");
    t["$session_entry_" + I(i)] = e;
  });
  return t;
}
```

The family is exactly `"$session_entry_" + sourceKey.replace(/^\$/, "")`, over the set-once property set, with `$current_url` renamed to `url` first. `$session_entry_url` and `$session_entry_referrer` are therefore not two names that were forgotten — they are two members of a family a **name list cannot enumerate**, because the producer mints the names at runtime from another property set. Round 6 missed them for a structural reason, and a seventh name added by a future `posthog-js` would be missed the same way.

**M2 — `$elements` is CONDITIONAL; `$elements_chain` is not.**

```js
nr({ $event_type: n.type, $ce_version: 1 }, u ? {} : { $elements: p }, { $elements_chain: … })
```

This refutes the obvious clean-room fix ("drop the serialized chain, keep the structured twin, let ingestion re-derive"): when `u` is truthy there is no structured twin, and dropping the chain would destroy autocapture outright rather than degrade it. The chain must be handled, not discarded wholesale.

**M3 — the chain's producer escapes some fields and strips others, and concatenates the rest raw.**

```js
if (t.tag_name) r += t.tag_name; // RAW — a quote survives
for (var s of t.attr_class) r += "." + s.replace(/"/g, ""); // quotes STRIPPED, not escaped
```

Attribute keys and values are escaped (`"` → `\"`); class names have quotes **deleted**; tag names are concatenated **raw**. Three different disciplines in one string. That is why every parse of it was defeatable, and it is why the design below never lets a chain parse **failure** mean "pass".

## Decision

### 1. One primitive: `safeUrlOrRedact`, deny-by-default, parser-serialized

Every URL-bearing value in both sinks — Sentry and analytics, scalar and chain and heatmap key — goes through one function. It returns either a value **rebuilt from URL parser fields** or `REDACTED`. There is no third outcome and no path that returns the input.

```
safeUrlOrRedact(raw):
  t := trim(raw)
  if t == ""                                   -> ""                      (nothing to leak)
  if t is an exact known sentinel ("$direct")  -> t                        (argued exemption, §4)
  if t contains ASCII whitespace or a comma    -> REDACTED                 (not ONE url; §2)
  if parse(t) succeeds (absolute):
      if scheme == "blob:"                     -> t                        (argued exemption, §4)
      if scheme not in SAFE_SCHEMES            -> REDACTED                 (§3)
      -> protocol + "//" + host + pathname
  if t starts with "//" and parse(t, BASE) ok  -> "//" + host + pathname   (protocol-relative)
  if parse(t, BASE) ok and origin == BASE      -> pathname                 (path-relative)
  -> REDACTED
```

Four properties, each closing a named defect:

- **Userinfo cannot survive, and not because a rule strips it.** The output is built from `host`, which is `hostname[:port]` by definition. `username`/`password` are never read, so there is no rule to forget at the next sink. `https://novakova:8001011234@evil.cz/x` reduces to `https://evil.cz/x` — the credential is gone structurally.
- **Query and fragment cannot survive**, for the same reason: they are never read.
- **A non-hierarchical scheme has no safe path to keep**, so it is not kept. `mailto:`, `tel:`, `data:`, `sms:`, `geo:`, `javascript:` and every scheme not on the list REDACT. Keying opacity on the absence of `//` was rejected: `data://text/csv,<payload>` round-trips through that test and still delivers its body. Membership is an **allow-list**, so an unknown scheme is denied by construction rather than by having been thought of.
- **No returned byte is unexamined.** Every non-redacted absolute answer is `protocol + "//" + host + pathname`, three fields the parser produced.

### 2. A value that is not ONE url is redacted whole

`reducesToSingleUrl`'s round-6 form asked whether a post-comma member was an _absolute_ URL, so `/a.png,//novakova:8001011234@evil.cz/x` was returned byte-identical at all four sinks in both repos: the later member was protocol-relative and therefore invisible to the test.

The replacement does not classify the members at all. **A URL-bearing value containing ASCII whitespace or a comma is not one URL, and is redacted whole.** `srcset`, `ping`, `imagesrcset` and any future list-valued attribute are covered without being named, and so is a single URL with a comma in its path — deliberate over-redaction, taken knowingly, because the alternative is a member-classification rule and member-classification rules are what the six rounds falsified.

This also disposes of framework binding syntaxes (`x-bind:href="isAdmin ? a : b"`): they contain whitespace, so they redact instead of being truncated at a ternary.

### 3. `SAFE_SCHEMES` — argued, not inherited

`http:`, `https:`, `ws:`, `wss:`, `file:`, `capacitor:`, `ionic:`. The last three are on the list because the web-native lineage ships a native build whose page URLs really are `capacitor://` and `file://` origins; excluding them would redact every page view on that platform, which is a functional break, not a safety gain. All seven are hierarchical and authority-or-path-bearing, so `protocol + "//" + host + pathname` is meaningful for each.

Membership is argued on **provenance**, in both directions: a scheme is added only when a producer we ship is shown to emit it, and removed when that stops being true.

### 4. Two exemptions, both argued, both pinned

- **`$direct`** is PostHog's sentinel for "no referrer". It is not a URL and must not be mangled into `/$direct`. Matched **exactly**, not as a prefix.
- **`blob:`** passes through. Its body is `<origin>/<uuid>` minted by `URL.createObjectURL` — browser-generated, never author-controlled text, with no query component to cut. It is exempt from the redact-to-scheme rule because there is nothing in it to redact, and redacting it would break media playback debugging for no gain.

Both are enumerated exemptions, which is the shape this ADR otherwise rejects — so both are stated as exemptions rather than hidden in a predicate, and each has a test that fails if the exemption widens (a `$direct`-prefixed value must still redact; a `blob:` with a query must still lose it).

### 5. The name vocabulary mirrors the producer's transform instead of listing names

One shared vocabulary serves the scalar path, the `$elements` object path and the `$elements_chain` value path — the round-4/round-5 defect was two vocabularies over the same DOM data, and the round-5 defect was one vocabulary consulted through two independently authored boundaries.

A key is URL-bearing when it matches, case-insensitively, after stripping a leading `$` and an `attr__` prefix:

- an exact member of the attribute set (`href`, `src`, `srcset`, `imagesrcset`, `ping`, `poster`, `action`, `formaction`, `cite`, `manifest`, `background`, `longdesc`, `lowsrc`, `dynsrc`, `codebase`, `usemap`, `data`, `profile`, `archive`, `pathname`), including namespaced forms such as `xlink:href` — matched on the **local name after the last `:`**, so `xlinkHref`'s rendered `xlink:href` is covered by the same rule that covers `href` rather than by a second one;
- or a name **ending in** `_url`, `_uri`, `_href`, `_referrer`, `_referer`, or equal to `url`/`uri`/`referrer`/`referer`.

The suffix rule is what makes `$current_url`, `$initial_current_url`, `$external_click_url` and `$session_entry_url` one rule rather than four entries.

**And the `$session_entry_` family inverts M1's transform.** For a key `$session_entry_<rest>`, the policy applied is the policy of the source key the producer derived it from: `$<rest>`, with `url` mapping back to `$current_url`. So `$session_entry_url` and `$session_entry_referrer` get the URL policy; `$session_entry_utm_source` keeps the free-text policy its source has and is not mangled into `/google`. A member added by a future `posthog-js` inherits its source's policy **without this file changing** — which is the whole point, and the reason round 6's two names are covered by construction rather than by having been added to a list.

### 6. `$elements_chain`: every parse failure REDACTS, and structure is examined

The chain is still parsed — M2 forbids discarding it — but the design of what a failed parse MEANS is inverted, and the structure half is no longer exempt.

1. An ambiguous escape (`\"` anywhere) → **REDACT the chain**. Previously this kept the chain whenever it carried no href, on the argument that the residue was bounded. ADR 1022 made that argument false and the code was not changed with it. It is not repaired; it is deleted.
2. Split on `"`. Verify alignment: every even segment except the last ends in `=`, and the last even segment is empty. On any misalignment → **REDACT the chain**. (Same policy, no href condition.)
3. **Even (structure) segments are examined.** They are tag names, class names and attribute names. If any contains `://`, `//`, `?` or `#`, the chain is **REDACTED**. A structure segment carrying a URL payload is anomalous — the realistic producer is a Tailwind arbitrary value such as `bg-[url(https://cdn.app.cz/i?sig=…)]`, and M3 shows class names are quote-**stripped** rather than escaped, so they cannot be rewritten in place without inferring a boundary. We do not infer it. We drop the chain. This closes the odd-index-only defect at its root rather than by adding an even-index pass whose boundary would be the next thing planted.
4. Odd (value) segments are scrubbed with the shared vocabulary: URL-bearing name → `safeUrlOrRedact`; otherwise the embedded-URL free-text pass.

The `@` byte is deliberately **not** a structure-segment marker. Tailwind v4 container queries (`@md:flex`, `@container`) put it in ordinary class names, and userinfo is unreachable without an authority, which `//` already catches. This is stated because it is the kind of narrowing that silently becomes wrong, and it has a test in both directions.

### 7. The composition root cannot fail open

`sanitizeProperties` stops being an optional prop whose absence means NO SCRUB. It becomes **required**. The package DAG still forbids `flags → telemetry`, so `@repo/flags` still cannot supply a default — but "cannot supply a default" argues for a required prop, not for a silent fail-open. A derived project that mounts `FlagsProvider` without a scrubber now fails to compile instead of shipping client-side PII with nothing red.

`$set_once` is scrubbed and now has a test that sends an event carrying it, so deleting that line reddens. The `$snapshot` short-circuit guard's test stand-in becomes a **recursive** scrubber, so deleting the guard reddens; the shallow stand-in was what made the old test vacuous, and a shallow fake cannot demonstrate a deep-walk hazard.

## Review discipline this ADR is written under

Binding, from the vault finding:

- **Assert SAFETY, never agreement.** A symmetry matrix comparing two code paths passes when both leak identically — that is exactly how the list-valued leak survived a matrix that already enumerated `attr__srcset`. Every parity assertion in this lineage now carries a "no payload marker survives" assertion beside it.
- **A green gate on a redaction surface is evidence about the TESTS, not about the code.** Six rounds, green throughout, four live leaks at the greenest moment.
- **Verifiers refute by default**, and a verifier that cannot produce an executed transcript has produced nothing.

## Consequences

- **More is redacted than before, deliberately.** Any `srcset`, any URL-bearing value with whitespace or a comma, any `mailto:`/`tel:`/`data:` href, any chain with an ambiguous escape or a payload-bearing class name. Autocapture detail is lost in those cases. That is the trade this ADR exists to make: the previous design kept that detail and shipped a surname and a rodné číslo with it.
- **The scheme allow-list is now a thing that must be maintained.** A derived project on a platform with its own scheme (an Electron `app://`, a browser-extension origin) will see its page URLs redacted until it argues that scheme onto the list. That failure is loud and safe, which is the intended direction.
- **`sanitizeProperties` becoming required is a breaking change** for any derived repo that mounts `FlagsProvider` — deliberately, since the break is a compile error and the alternative is silence.
- The wip branches `wip/w7-redaction-rounds` (fullstack `9792448`, web-native `c4ebc21`) remain as history. Their **tests** are the value and are ported; their implementation is reference only and is never a rebase base.
